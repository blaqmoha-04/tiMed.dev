Start with structure: semantic HTML

Meaningful elements make a page easier to understand, navigate and maintain.

HTML does more than place content on a screen. Its elements describe what that content is, giving browsers and assistive technologies useful structure.

Choose elements for their meaning

Use a <main> element for the page's primary content, a <nav> for important navigation, and headings to organize sections. A button should trigger an action; a link should take someone somewhere.

These choices make the document easier to scan and give keyboard and screen-reader users familiar ways to move through it.

Build a clear heading outline

Start with one descriptive page heading, then use lower-level headings to introduce related sections. Choose heading levels for the content hierarchy rather than their default visual size; CSS can control appearance.

Make forms understandable

Give each input a visible label and connect it to the control. Placeholder text can offer an example, but it should not replace a label because it disappears as someone types.

Check the page with a keyboard

Try moving through links, buttons and form controls with Tab and Shift+Tab. Keep the focus indicator visible and make sure each control has a useful name. Semantic HTML provides a strong starting point, but real interaction testing still matters.
